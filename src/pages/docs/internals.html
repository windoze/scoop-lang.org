编译器与运行时架构

Scoop 的编译器用 Rust 编写，经过 AST → HIR → MIR → LIR 四层 IR，再由 LLVM 生成原生对象代码；运行时用 C 编写，提供精确移动 GC、异常展开、协程与 FFI 支持。本页概述各组成部分及其职责。

阶段职责
Parser / AST保留原始源码顺序、byte span、显式类型实参、各种实参形式以及声明、表达式、模式与控制转移结构。可恢复的语法分析同时服务于语言服务。
HIR名称解析、重载决议、类型推断与检查、smart cast、可见性、穷尽性、effect（suspend / NoGC / unsafe）检查。输出导出模板（供下游 Cone 实例化泛型）与本 Cone 的具体化 HIR。
MIR只接收已具体化的 HIR；每个表达式具有精确类型，调用与短路求值展开为 CFG，并严格保持求值顺序。协程状态机、闭包环境、装箱在此层显式化。
LIR以完整操作表达托管分配、字段/数组写入、值复制、原子访问、safepoint poll 与 release 发布，携带实际类型、布局、GC effect 和 live set。
Codegen通过 inkwell 调用外部 LLVM 22.1：内联分配与写屏障快路径、statepoint 与 stackmap、异常 landing pad、接口派发表与 C ABI 桥接，生成目标对象代码。

每个阶段 crate 只依赖自己的输入/输出 IR crate，不依赖上游阶段的实现；阶段之间的编排由 driver 负责。IR 的数据结构在结构上保证完备——例如表达式的类型信息不可能缺失——而不是依赖后续检查兜底。全局实体都有类型化的唯一 id：泛型函数、已解析类型参数的泛型函数与单态化后的函数是三种不同的实体类型。

工具组成

命令职责
scoop面向用户的工具入口：从 PM 取得精确依赖图和本地输入，判断更新并调度构建、链接与测试，同时提供格式化、前端检查和文档生成。
scoop-pm / scoop pm独立包管理器：读取 Cone/workspace 清单，解析版本要求，取得 Git/registry 源码，维护 Cone.lock，向构建工具提供精确图。自身不依赖 LLVM。
scoopc单 Cone 编译器：一次只编译一个 Cone，只消费命令行显式给出的依赖产物，不读取上游源码。
scoop-link把一组 .slib 产物与运行时链接成可执行文件。
scoop-lsp语言服务器，复用编译器前端的语义查询，提供诊断、补全、导航和重构。
scoop example随工具链分发的外部子命令，按主题或关键词查询离线示例。
lldb / lldb-dap随工具包分发的原生调试器与 VS Code 调试适配器，读取编译器生成的调试信息与 Scoop 类型展示。

.slib 产物与缓存

每个 Cone 编译为一个 .slib：目标相关、按位可复现的 ar 归档，首项是 Zstandard 压缩的 CBOR manifest，其余成员保存 HIR/MIR/LIR 元数据与目标对象代码。下游 Cone 通过 .slib 中的导出模板实例化泛型、内联跨 Cone 函数，而不需要重新读取依赖的源码。

  • Cone 身份由完整的 group:name:version 坐标决定，产物另有内容指纹；
  • 版本要求在编译前由 PM 解析并写入 Cone.lock；scoopc、链接器与 runtime 消费静态精确图，不再求解版本；
  • 一个最终程序内，同一个 group:name 只有一个版本和一个来源；workspace 中不同根程序可以有不同选择；
  • 缓存只判断“输入是否变化”：未变化且结果存在时直接复用，不回读产物做额外复核；
  • 标准库以预编译 .slib 随工具链发布，普通应用不需要重新编译它们。

源码缓存与编译缓存分别管理：Git/registry 源码默认共享在 ~/.scoop/packages/，构建结果保存在项目输出和 Cone 构建缓存中。普通构建优先复用相容的锁定选择；scoop pm update 请求更新版本，--locked 禁止改变锁定选择，--frozen 同时禁止联网。详见Cone.toml 与依赖及registry 指南。

对象模型

  • 托管引用是指向对象起点的直接指针，对象可能被 GC 移动；对象头固定 16 字节：TypeDescriptor 指针 + GC 状态字；
  • 接口值是双字的 { object, itab }：itab 指向实际类型对该接口的完整槽表，接口调用直接读取槽位，不在运行时查目录；
  • class、Any、String、数组与函数值是单字引用；
  • 值类型内联存储，转为引用类型时装箱；零尺寸类型（ZST）不占存储，但保留类型身份；
  • Option 利用 niche 表示：引用、Ptr、FunPtr 的 None 用空指针表示，不需要额外的 tag。

垃圾回收

运行时实现精确、移动、分代的 Immix 风格收集器：

  • 精确根：编译器通过 LLVM statepoint 与 stackmap 记录每个 safepoint 上存活的引用，GC 后按 stackmap 更新重定位；
  • 分配：线程本地 TLAB 中 bump 分配，快路径由 codegen 内联；对象按 Immix 的 block / line 组织；
  • 分代：minor collection 处理年轻代，借助卡表写屏障追踪旧代到年轻代的引用；full collection 处理整个堆，并按回收收益选择 region 进行搬迁整理；
  • 并行标记：stop-the-world 后由常驻 worker 线程并行 mark；
  • 分片收集：默认对旧代压力触发的 full collection 分片标记，片间恢复程序执行；minor 默认完整收集。分片期间不搬迁对象，标记线程不与程序并发读取普通对象字段；
  • pin 与 handle：FFI 期间可以 pin 对象或持有 handle，被 pin 的对象不移动；
  • release hook：带 release 块的对象在回收前尽力调用一次 GC-free 的清理逻辑。

调试 GC 时可以用 scoop --enable-gc-stress run … 链接 stress 版本的运行时，再在运行时设置 SCOOP_GC_STRESS_MOVE=1 或 SCOOP_GC_STRESS_MINOR=1 开启移动或 minor 收集的压力模式；--enable-startup-stats 输出启动计时与元数据统计。

运行时的其他职责

  • 异常：基于原生 unwind 的 personality 与 landing pad，catch 时物化托管异常对象；
  • 初始化：object / companion 单例与全局初始化按初始化单元一次性执行，失败会被缓存；
  • 线程：mutator 线程登记、safepoint 握手、native 状态切换；
  • 协程与 Context：协程帧与续体由编译器生成，运行时负责 task-local Context 的绑定与传播；
  • FFI 支持：Scoop ABI 的 runtime functions（分配、root、pin、handle、托管回调）与 C 头文件 scoop_rt.h。

运行时不重新进行名称解析、重载选择或泛型实例化——这些都在编译期完成。

异步 I/O 驱动属于普通库 scoop.asyncio。PlatformEventLoop 在 Darwin 使用系统 libdispatch，在 Linux 使用 io_uring/liburing；任务树复用 core 的 Job/CoroutineScope。原生 callback 与 worker 只产生完成记录，由所属事件循环推进 I/O continuation；宿主主循环可通过 attach 接入。它不增加编译器内建调度器或新的 runtime ABI。

规范文档

Scoop 遵循“spec 先行”：语言行为、运行时契约与流水线职责的变更都先修改规范。主要文档（中文）：

  • 语言规范：语法、类型系统、核心库与 FFI；
  • 运行时规范：对象模型、GC 契约、异常与运行时函数；
  • 编译器与产物规范：各阶段的输入输出、实体身份、目标 ABI、.slib 格式与链接契约；
  • 包管理规范：workspace、版本要求、Git/registry、锁文件与构建接入；
  • 路线图：实现里程碑；
  • 库规范：std、asyncio、HTTP、TLS、JSON、正则、终端等各库的 API 合同。
