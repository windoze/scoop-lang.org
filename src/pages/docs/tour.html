语言导览

这份导览通过一组可运行的小程序介绍 Scoop 的主要特性。每段代码都附有实际运行输出，你可以把它保存为 .scoop 文件，用 scoop run 运行。如果你熟悉 Kotlin，大部分语法会很眼熟；差异集中整理在对比 Kotlin一页。

基础

程序从 fun main() 开始。val 声明不可重新赋值的绑定，var 声明可变变量；类型可以省略，由编译器推断。if、when 和 try 都是表达式。

{{example basics}}
  • 字符串插值只在 f-string 中生效：f"…${expr}…"，花括号不能省略；普通字符串里的 $ 就是普通字符。
  • """…""" 与 f"""…""" 是保留换行的 raw 字符串。
  • 1..3 是闭区间，0 until n 是半开区间。

数值类型

整数有八种定宽表示：Int8/Int16/Int/Long 与对应的无符号 UInt8/UInt16/UInt/ULong，Int 在所有目标上固定 32 位，Long 固定 64 位；Byte、Short、Int64 等是透明别名。浮点数有 Float 与 Double。

  • 字面量：42、42L、42u、42uL、0xFF、0b1010、1_000_000；
  • 不同宽度或符号的整数之间不做隐式提升，需要显式调用 toLong()、toUInt() 等；
  • 算术溢出按二进制补码回绕，不抛异常；整数除零抛出 ArithmeticException；
  • 集合长度和下标使用 Long，例如 names[0L]、text.charLength。

struct：值类型

struct 是不可变的聚合值类型：没有 identity，按值复制，作为字段或数组元素时内联存储。字段在主构造函数中用 val 声明，可以带默认值，构造时可以使用命名参数。

{{example structs}}
  • 副本更新 p.{ y: 10 } 基于已有值创建修改了部分字段的新值，原值不变；
  • struct 自动获得逐字段的结构相等 ==；值类型上使用 === 是编译错误；
  • 解构可以按位置 val (x, y) = p，也可以按字段名 val Config { host, port, .. } = config，.. 忽略其余字段；
  • tuple 是匿名的积类型：(1, "one")，通过 ._1、._2 或解构访问；() 就是 Unit，1 元 tuple 写作 (e,)；
  • ToString、Hash 不会自动派生，需要像上面那样显式实现。

enum 与模式匹配

Scoop 的 enum 是带载荷的代数数据类型（类似 Rust）。变体可以没有载荷、携带位置参数，或携带命名字段。when 中以 case 开头的分支使用模式语义，可以嵌套匹配 enum、tuple 和 struct，并用 if 添加 guard。

{{example enums}}
  • 在 case 中，变体名可以省略 Shape. 前缀，由 subject 的类型解析；
  • 含 case 的 when 必须穷尽，否则编译器会报错并给出一个未覆盖的示例；带 guard 的分支不计入覆盖；
  • enum Status: Int { … } 声明整型枚举：每个变体有显式数值，可以按值上转为 Int，但整数不能隐式转回枚举；
  • 变体不是类型，不能用于 is 检查或作为变量类型，提取载荷一律通过 when。

Option：没有 null

Scoop 没有运行期 null。T? 只是核心库 enum Option<T> { Some(T), None } 的语法糖，Kotlin 的空安全运算符照常使用：

{{example options}}
  • a?.b：a 为 Some(v) 时得到 Some(v.b)，否则为 None；
  • a ?: b：取 Some 的载荷，否则求值 b（可以是 return 或 throw）；
  • a!!：取载荷，None 时抛出 UnwrapException；
  • 可空是逐层的：T?? 是 Option<Option<T>>，Some(None) 与 None 可以区分；安全调用不会展平结果；
  • Option 是普通 enum，可以直接在 when 里深度匹配，例如 case Some(User { email: Some(addr), .. })。

类、接口与对象

类、接口、object 和 companion object 是引用类型，语法与 Kotlin 一致。类和方法默认 final，需要 open 才能被继承或覆写；接口方法可以有默认实现；扩展函数为已有类型添加方法。

{{example classes}}
  • 值类型（struct / enum）也可以实现接口；转为接口或 Any 时自动装箱；
  • 引用类型的 === 比较对象 identity；== 只决议静态类型上可见的 operator fun equals，不存在 Any.equals 回退；
  • 默认可见性是 internal（Cone 内可见）；覆写 public 接口成员（如 ToString.toString）时需要写 public override；
  • sealed class / sealed interface 限定直接子类型，配合 when 做穷尽检查（见运算符一节的例子）。

泛型

函数、class、struct、enum 和 interface 都可以有类型参数。泛型采用单态化：每组具体类型实参生成一份专门代码，没有类型擦除，也不需要 reified。类型参数用上界约束能力，例如 T : Compare<T> 允许使用比较运算符。

{{example generics}}
  • 所有类型参数都是不变的：没有 in/out 型变和 * 投影，Box<String> 不是 Box<Any> 的子类型；
  • 调用处可以显式写类型实参，也可以用 _ 只写一部分：convert<Int, _>(value)；
  • where 子句、条件接口实现与负向约束等高级特性见语言规范 3.2、9.1.8 节。

函数值与集合

lambda 写作 { x -> body }，单参数可以用 it；最后一个函数参数可以写成尾随 lambda。scoop.collections 提供 List、HashMap、LinkedHashMap、TreeMap 等集合以及 filter/map/sorted 等常用操作。

闭包不能捕获 var

Scoop 的闭包在创建时按值捕获环境，只允许捕获 val、参数和 this，读写外层 var 都是编译错误。需要在多个闭包之间共享可变状态时，显式捕获一个引用对象（如上例的 Cell）。

还可以使用 fun(x: Int): Int { … } 匿名函数、::name 函数引用、默认参数、命名参数和 vararg。

异常

try/catch/finally 与 throw 和 Kotlin 一致，try 也是表达式。异常类继承自 Exception，消息是 String?。

{{example errors}}

标准库的命名约定：可能失败的解析/查找提供抛异常版本与返回 Option 的 …OrNone 版本，例如 toInt() / toIntOrNone()。

协程与异步 I/O

Scoop 支持 suspend 函数与挂起 lambda suspend { … }。核心库提供协程原语和结构化并发（Job、Deferred、作用域取消）；scoop.asyncio 的 PlatformEventLoop 提供定时器、TCP/UDP 与文件 I/O，macOS 后端使用 libdispatch，Linux 后端使用 io_uring：

{{example coroutines}}
  • scope.async 启动返回值的任务，scope.launch 启动不返回值的任务，await() / join() 等待完成；
  • 任务树是结构化的：父作用域结束前等待所有子任务。取消是协作式的，由任务检查或支持取消的挂起操作观察，异常退出时 finally 照常执行；不会抢占正在执行的普通代码；
  • PlatformEventLoop 只运行一次，不能嵌套启动或在结束后复用。Linux 后端要求内核 6.1 及所需 io_uring 能力；详见平台与异步 I/O；
  • Scoop 支持多线程，但不在类型系统中保证无数据竞争；跨线程共享数据需要使用原子类型（Atomic*，带显式内存序）或同步原语。

确定性资源管理

托管对象由 GC 回收，但文件、套接字、正则引擎等原生资源需要确定性释放。同步 I/O 和具有关闭语义的对象实现 Closeable.close()，用 use 在正文正常或异常退出时关闭；需要挂起关闭的对象实现 AsyncCloseable，使用 useAsync：

{{example regex}}

Closeable 继承 Disposable，默认 dispose() 转调 close()，因此复用同一套 use。取消登记、锁、线程等一般资源仍使用 Disposable.dispose()。如果正文和清理都失败，use/useAsync 用 ResourceUseException 保留两个错误。

直接持有原生资源的 final class 还可以声明 release { … }，在对象被 GC 回收时尽力清理。它不保证执行时间或程序退出时执行；只能使用满足 release-safe 规则的 GC-free 操作和 helper，不能分配托管对象、挂起或通过原生调用回调 Scoop。确定性释放依靠显式 close、use 或 useAsync，不能用 @NoGC 或 release 替代：

C FFI

@Extern 把没有函数体的顶层函数绑定到原生符号。C ABI 的 extern 是 unsafe 函数，只能在 @Unsafe 上下文中调用；签名上只能出现 C 兼容（GC-free）的类型。

{{example ffi}}
  • Ptr<T> 是原生指针，FunPtr<F> 是 C 函数指针，sizeOf<T>() / alignOf<T>() 查询布局；
  • @CLayout struct 按 C 规则布局，可以按值传给 C 函数；
  • @Extern(lib = "…") 指定逻辑库名，captureErrno = true 让调用同时返回 errno；
  • @NoGC 标注保证函数不分配托管对象、不进入 GC；@Global / @ThreadLocal 声明原生全局存储；
  • Cone 可以携带 C/C++ 源码，与 Scoop 代码一起编译链接。

编码、解码与类型描述

在 companion 上声明 ValueEncoder<T> / ValueDecoder<T>，编译器就会为 struct 合成编解码实现，供 JSON、命令行参数、HTTP 查询参数等不同格式复用：

{{example cli}} 
$ scoop run --release cli.scoop Ada --count 2 --excited

typeInfo<T>() 返回编译器生成的静态类型描述（字段、注解、构造关系），用于上面的命令行 schema 这类场景；Scoop 不提供运行期反射。

package 与 import

Cone 中的每个文件以 package 声明开头，再用 import 引入其他包的名称：

package dev.example.app

import scoop.collections.*          // 整个包
import scoop.time.Duration          // 单个名称
import scoop.io.encoding.Base64

核心库的 prelude（println、Option 及其变体 Some/None、ArrayList、StringBuilder 等）默认可见。可见性修饰符有 public、internal（默认，Cone 内可见）、protected 和 private。

测试

测试放在 Cone 的 tests/ 目录中，依赖 scoop.test（在 [test-dependencies] 中声明）。用 @Test 标注测试类与测试方法，方法名可以用反引号写成一句话：

package examples.testing

import scoop.test.*

@Test
private class CalculatorTests {
    @Test
    fun `division returns a value`() {
        assertEquals(6, divide(42, 7))
        assertTrue(divide(42, 7) > 0)
    }

    @Test
    fun `zero count reports the reason`() {
        val error = assertFailsWith<IllegalArgumentException> { divide(42, 0) }
        assertEquals(Some("count must not be zero"), error.message)
    }
}

scoop test 运行选中的用例并逐项报告结果；断言库还提供前后置钩子、忽略标记等功能，见 scoop.test 的 API 文档。
