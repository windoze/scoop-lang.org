协程与并发

Scoop 在语言层提供 suspend 函数和最小的协程原语，核心库在其上实现结构化并发；事件循环与异步 I/O 由 scoop.asyncio 提供。Scoop 也支持多线程，但不在类型系统中保证没有数据竞争，跨线程共享状态需要显式使用原子类型或同步原语。

suspend 函数

suspend fun 声明可以挂起的函数。挂起函数只能在另一个挂起函数或挂起 lambda（suspend { … }）中调用；main 必须是普通函数，从普通代码启动挂起计算使用核心库的 startCoroutine 或事件循环。

  • 调用挂起函数可能立即在当前调用栈内得到结果，也可能保存当前计算、稍后恢复；无论哪种情况，调用方都只观察到一次普通的返回值或一次在调用点抛出的异常。
  • 挂起前已经求值的实参不会重新求值，跨挂起点存活的局部变量会被保留，源码的从左到右求值顺序不变。
  • 挂起不是退出：finally 不会因为挂起而执行；以异常恢复等价于在挂起点 throw。
  • 挂起性是签名的一部分：覆写必须保持一致，suspend (A) -> R 与 (A) -> R 不兼容；普通 lambda 不会自动变成挂起 lambda。只相差 suspend 的两个函数是重复声明。
  • 以下位置不能挂起：顶层属性与 object 的初始化、类的构造函数、属性初始值与 init 块、默认参数（挂起函数自身的默认参数除外）、属性的 getter/setter 与委托协议。需要异步取得的值应暴露为挂起函数。
  • 不支持挂起的 FFI：@Extern 函数不能是 suspend。

协程原语

核心库定义了支撑 suspend 的最小接口：

interface Continuation<T> {
    fun resume(value: T)
    fun resumeWithException(exception: Throwable)
}

fun <T> startCoroutine(task: suspend () -> T, completion: Continuation<T>)
suspend fun <T> suspendCoroutine(registration: (Continuation<T>) -> Unit): T
  • startCoroutine 启动挂起计算后立即返回；计算完成时（可能在返回之前）恰好调用一次 completion。
  • suspendCoroutine 把当前 continuation 交给 registration。可以同步恢复它，也可以保存起来以后恢复。
  • Continuation 只能完成一次：再次调用 resume 或 resumeWithException 抛出 IllegalStateException。丢弃一个永不恢复的 continuation 不会执行其中的 finally。
  • 两者也有接受 SuspendTask<T>、SuspendRegistration<T> 接口的重载，语义相同。原语本身不切换线程，也没有事件循环。
class Report : Continuation<Int> {
    public override fun resume(value: Int) {
        println(f"completed with ${value}")
    }
    public override fun resumeWithException(exception: Throwable) {
        println("failed")
    }
}

class Gate {
    var waiting: Continuation<Int>? = None
    suspend fun await(): Int = suspendCoroutine<Int> { c -> waiting = Some(c) }
    fun open(value: Int) {
        val c = waiting!!
        waiting = None
        c.resume(value)
    }
}

suspend fun compute(gate: Gate): Int {
    println("waiting")
    val v = gate.await()            // 真正挂起：startCoroutine 返回给 main
    println("resumed")
    return v * 2
}

fun main() {
    val gate = Gate()
    startCoroutine(suspend { compute(gate) }, Report())
    println("started")
    gate.open(21)                   // 恢复协程，最终输出 completed with 42
}

结构化并发

核心库在原语之上提供结构化的任务树：

声明作用
suspend fun <T> coroutineScope(block: suspend (CoroutineScope) -> T): T建立子作用域；等待正文与所有子任务完成后才返回
scope.launch(block: suspend () -> Unit): Job启动不返回值的子任务
scope.async<T>(block: suspend () -> T): Deferred<T>启动返回值的子任务
job.join() / deferred.await()等待任务结束 / 取得结果或重新抛出其异常；可以多次调用
job.cancel()、isCancelled、isCompleted请求取消与查询状态
ensureActive()、currentJobOrNone()在当前任务已取消时抛出 CancellationException；取得当前 Job
job.invokeOnCancellation(handler)登记取消回调，返回可撤销登记的 Disposable
nonCancellableScope(block)在取消之后仍需完成的异步清理
suspendCancellableCoroutine(registration)能被所属任务取消的挂起点

使用这些 API 需要一个驱动协程的事件循环。scoop.asyncio 的 PlatformEventLoop.run 是同步的根入口：它建立根作用域，运行到根正文和全部子任务完成后返回。

//! dep: scoop:scoop.asyncio:0.1.0

import scoop.asyncio.*
import scoop.time.Duration

fun main() {
    val loop: EventLoop = PlatformEventLoop()
    loop.run suspend { scope ->
        val total = coroutineScope<Int> suspend { inner ->
            val a = inner.async<Int> suspend {
                loop.sleep(Duration.milliseconds(10L))
                1
            }
            val b = inner.async<Int> suspend { 2 }
            a.await() + b.await()
        }
        println(total)                                   // 3
    }
}
  • 子任务先登记到父任务再启动，可能在 launch/async 返回之前就同步完成。
  • 作用域在正文结束后不再接受新的子任务，并在所有已登记的子任务完成后才发布结果。
  • 子任务的失败（取消以外的异常）立即传播给父任务，并请求取消其他子任务；coroutineScope 先等子树收尾，再在调用点重新抛出这个失败，调用方可以捕获。未被 await 的 async 失败同样会传播。
  • 每个 Job 保留首个记录的失败，后续的独立失败不会覆盖它。
  • 子任务继承启动时的 Context 绑定快照。

取消

取消是协作式的：cancel() 向任务及其后代发出请求，被取消的任务在检查点（ensureActive()、可取消的挂起操作，如事件循环的 sleep 与 I/O）抛出 CancellationException，finally 照常执行。正在执行的普通代码不会被抢占，原始的 suspendCoroutine 也不会自动观察取消。

//! dep: scoop:scoop.asyncio:0.1.0

import scoop.asyncio.*
import scoop.time.Duration

fun main() {
    val loop: EventLoop = PlatformEventLoop()
    loop.run suspend { scope ->
        val worker = scope.launch suspend {
            try {
                while (true) {
                    loop.sleep(Duration.milliseconds(5L))   // 可取消的挂起点
                }
            } finally {
                println("worker cleanup")
            }
        }
        loop.sleep(Duration.milliseconds(20L))
        worker.cancel()
        worker.join()
        println(f"cancelled=${worker.isCancelled}")

        try {
            coroutineScope<Unit> suspend { s ->
                s.launch suspend { throw IllegalStateException(Some("child failed")) }
                loop.sleep(Duration.milliseconds(50L))
            }
        } catch (e: IllegalStateException) {
            println(f"caught ${e.message ?: ""}")
        }
    }
}
  • 单独取消子任务不会取消父任务；取消父任务会传播给所有后代。
  • join/await 的等待可以被等待者自身的取消打断，但这不会取消被等待的任务。
  • coroutineScope 内部等待子树收尾时不会被调用方的取消提前打断。
  • 取消之后需要挂起才能完成的清理放在 nonCancellableScope 中。
  • suspendCancellableCoroutine 的取消只结束等待，不保证外部操作已经停止；借用调用方缓冲区的 I/O 必须等到确认不再使用缓冲区后才能恢复。

事件循环

PlatformEventLoop 在 macOS 上使用 libdispatch，在 Linux 上使用 io_uring（要求内核 6.1 及所需能力，能力不足时报错而不是切换后端），在 Windows 上使用 IOCP（overlapped socket 与文件句柄，取消通过 CancelIoEx 撤销在途请求）。它提供定时器、TCP/UDP、DNS、异步文件与目录、TTY 等操作。run 只能调用一次，不能嵌套或在结束后复用；已有宿主主循环的程序使用 attach。详见库 Cone 一览与 异步 I/O 规范。

线程与数据竞争

scoop.platform.concurrent 提供 Thread、Mutex、ConditionVariable 等同步原语。Scoop 不提供 Rust 或 Swift 式的并发安全保证：

  • 数据竞争是指不同线程访问同一存储位置，至少一个是写、至少一个是非原子访问，且二者之间没有 happens-before 关系。
  • 数据竞争是未定义行为：可能读到无效的值、撕裂的值或破坏内存安全。普通字段、数组元素、全局变量与原生内存都适用，值类型与引用类型没有区别。
  • happens-before 由线程内的求值顺序、原子操作与同步原语按其契约建立。val 不自动提供跨线程同步；通过原子引用发布对象时，必须使用能建立同步的内存序。
  • GC、写屏障与 safepoint 不替代用户数据的同步。
//! dep: scoop:scoop.platform:0.1.0

import scoop.platform.concurrent.*

fun main() {
    val counter = AtomicLong(0L)
    val threads = ArrayList<Thread>()
    for (i in 0 until 4) {
        threads.add(Thread.start {
            for (j in 0 until 1000) counter.fetchAdd(1L)
        })
    }
    for (t in threads) t.join()
    println(counter.load())                     // 4000

    val lock = Mutex()
    val value = lock.withLock { 42 }
    lock.dispose()
    println(value)
}

main 返回时仍有未 join 的线程是关闭失败：程序报告剩余线程数并以退出码 1 结束。需要带着后台线程直接结束进程时调用 exit(code)。协程任务与线程是不同的概念：结构化并发不承诺任务在哪个线程上运行。

原子类型

核心库提供 AtomicInt、AtomicLong、AtomicBoolean 与 AtomicRef<T : ref>，构造时传入初值。它们是 final class，复制引用访问的是同一个存储位置。

方法语义
load(order) / store(value, order)原子读 / 写
exchange(value, order)写入并返回旧值
compareAndSet(expected, value, successOrder, failureOrder)相等时写入，返回是否成功（strong CAS）
compareAndExchange(…)同上，返回观察到的旧值
fetchAdd fetchSub fetchAnd fetchOr fetchXor原子更新并返回旧值（整数按位宽回绕；AtomicBoolean 只有位运算）
getAndUpdate(f) / updateAndGet(f)基于 CAS 循环的更新，f 可能因竞争被调用多次
  • 内存序 MemoryOrder 有 Relaxed、Acquire、Release、AcqRel、SeqCst，默认 SeqCst，语义与 C11 一致。
  • 内存序必须是编译期常量（直接写出的变体或默认值），非法组合是编译错误：load 只接受 Relaxed/Acquire/SeqCst，store 只接受 Relaxed/Release/SeqCst，CAS 的失败序不能是 Release/AcqRel，也不能强于成功序。
  • AtomicRef 的 CAS 比较对象 identity，不调用 equals；读取原子引用不会同步所指对象之后的普通字段访问。
  • 原子类型不实现 Equals、Hash 或 ToString；比较时显式 load()。
  • Atomic<T : value> 用一个内部锁保护任意值类型，提供 load、store 与 exchange，适合需要整体原子替换的小型结构。
fun main() {
    val ready = AtomicBoolean(false)
    println(ready.compareAndSet(false, true, MemoryOrder.AcqRel, MemoryOrder.Acquire))   // true
    val name = AtomicRef<String>("a")
    println(name.exchange("b"))                     // a
    val n = AtomicInt(5)
    println(n.updateAndGet { it * 2 })              // 10
    val point = Atomic<(Int, Int)>((1, 2))
    point.store((3, 4))
    println(point.load()._1)                        // 3
}
