原生互操作

Scoop 通过 @Extern 直接绑定 C 符号，不需要生成胶水代码。C ABI 的边界上只能出现不含托管引用的类型；对原生内存的操作必须写在 @Unsafe 上下文中。Cone 还可以携带 C/C++ 源码，与 Scoop 代码一起编译链接。

@Extern 函数

@CLayout
struct DivResult(val quot: Int, val rem: Int)

@Extern(name = "div")
fun cDiv(numerator: Int, denominator: Int): DivResult

@Extern(name = "strlen")
fun cStrlen(text: Ptr<Int8>): ULong

fun main() {
    @Unsafe {
        val d = cDiv(17, 5)
        println(f"${d.quot} ${d.rem}")              // 3 2
        val n = "héllo".withCString { p -> @Unsafe { return@withCString cStrlen(p) } }
        println(n)                                  // 6：UTF-8 字节数
    }
}
annotation class Extern(val lib: String = "", val name: String = "", val abi: String = "c", val captureErrno: Boolean = false)
  • @Extern 只能用于顶层、非泛型、非挂起的函数，函数体必须省略。name 是原生符号名，省略时使用声明名；lib 是逻辑库名（不是路径），对应清单中的 [[native.libraries]]，空串表示默认命名空间（如 libc）。
  • C ABI（默认 abi = "c"）的 extern 函数是 unsafe 的，只能在 unsafe 上下文中调用。
  • 签名中的每个参数与结果都必须是 C-FFI-safe 的类型；String、数组、class 等托管引用出现在 C 边界上是编译错误。
  • 不支持 C 的可变参数（printf 式的 ...），需要时用 C 包装函数。Scoop 的 vararg 也不能用于 C extern。
  • extern 声明可以带 Scoop 默认参数，它们在调用方求值，原生函数总是收到完整的参数列表。
  • 同一程序中引用同一原生符号的多个声明，签名必须一致，否则是链接错误。
  • @CallingConvention(name) 可以为 extern 指定调用约定。

@Unsafe 与 @Safe

unsafe 操作包括调用 C extern、调用标注 @Unsafe 的函数（例如 Ptr.load、addressOf）以及读写 unsafe 的构造函数或访问器。它们只能出现在 unsafe 上下文中：

  • 标注 @Unsafe 的函数、构造函数或访问器的函数体；
  • @Unsafe { … } 语句块。

@Safe 在 unsafe 上下文中重新引入安全约束。几点需要注意：

  • @Unsafe { … } 是语句，不是表达式，不能用作值；需要结果时在块中赋值给外部的 var，或在 lambda 中用 return@label 返回。
  • unsafe 上下文不延伸到其中的 lambda 与局部函数：lambda 是独立的函数值，其中的 unsafe 调用需要自己的 @Unsafe 块（如上例的 withCString）。
  • 标注 @Unsafe 的函数在调用方同样需要 unsafe 上下文。

Scoop 的整数宽度是固定的，不会把 Int 映射为 C 的 int 或 long：绑定 C 函数时请按其头文件中的实际宽度选择类型，例如 64 位平台上的 size_t 对应 ULong；注意 Windows 是 LLP64，C 的 long 在 Windows 上是 32 位（Int），在 macOS/Linux 上是 64 位（Long），这类类型需要用 按目标选择的源码分别声明。裸 Ptr 永远非空，原生函数声明返回 Ptr<T> 却返回了 NULL 属于契约违反，可能返回 NULL 时请声明为 Option<Ptr<T>>。零大小类型（除作为结果的 Unit 外）不能出现在 C 边界上。

@CLayout

@CLayout(aligned = 0L, packed = 0L) 让 struct 按 C 规则布局，可以按值传给 C 函数或通过指针共享。所有字段必须递归地具有稳定的 C 表示，不能包含托管引用或零大小字段；没有字段的 @CLayout struct 是编译错误。aligned 提高 struct 的最小对齐，packed 限制字段的对齐，取值为 1L、2L、4L、8L 或 16L，0L 表示不调整。

@NoGC

@NoGC 断言函数不与 GC 交互：不读写任何托管引用，也不分配托管对象。编译器在编译期检查这一点。

  • 参数、结果与局部值都必须是 GC-free 的类型（递归地不含托管引用）。class 的方法有隐式的引用接收者，因此 @NoGC 成员函数只能属于值类型。
  • 用于 struct 或 enum 时，表示该类型必须是 GC-free 的；泛型类型在每个具体实例上检查。
  • 泛型 @NoGC 函数在每个具体实例上检查：identity<Int> 合法，identity<String> 是编译错误。
  • 作为原生回调地址的函数必须是 @NoGC 的，见 FunPtr。
@NoGC
fun clamp(value: Int, low: Int, high: Int): Int = if (value < low) low else if (value > high) high else value

@NoGC
struct Sample(val time: Long, val value: Double)

fun main() {
    println(clamp(12, 0, 10))
}
@NoGC
fun size(text: String): Long = text.byteLength    // 编译错误：String 是托管引用

@GCLeaf

普通的 C extern 调用会让当前线程进入“原生安全”状态，使 GC 可以在调用期间并发工作。@GCLeaf 为短小的 C 函数省去这次状态切换，调用开销接近直接的 C 调用。作为交换，FFI 作者必须保证该函数及其同步调用的一切：不回调 Scoop、不进入运行时，不阻塞等待（I/O、锁、sleep、join 等），并且尽快返回——执行缓慢会延迟 GC。违反这些约束属于未定义行为，编译器无法检查。

@GCLeaf
@Extern(name = "abs")
fun cAbs(x: Int): Int

fun main() {
    @Unsafe {
        println(cAbs(-4))
    }
}

捕获 errno

captureErrno = true 让调用同时返回 C 函数返回时的 errno。声明的结果必须写成 (R, Int)，其中 R 是原生函数的结果类型（void 写作 Unit）：

@Extern(name = "close", captureErrno = true)
fun closeWithErrno(fd: Int): (Int, Int)

fun main() {
    @Unsafe {
        val (result, error) = closeWithErrno(-1)
        println(f"${result} ${error}")     // -1 和 EBADF 的值
    }
}

调用前 errno 被清零，原生函数返回后立即读取，因此结果不受之后的分配、GC 或其他调用影响。是否失败仍由 C 函数的返回值决定，Scoop 不会自动抛出异常。只有 C ABI extern 函数可以启用它。

Ptr 与 addressOf

Ptr<T : value> 是指向 GC-free 值类型的原始指针，本身也是值类型。除 == 外，它的操作都是 unsafe 的：

操作说明
p.load() / p.store(v)读写所指的值
p.load(i) / p.store(i, v)按元素偏移读写
p + n / p - n按元素个数移动（字节偏移为 n * sizeOf<T>()）
p.cast<U>()重新解释指针类型
p.toULong() / Ptr<T>(raw)与整数地址互相转换；raw 必须非零
addressOf(v)取局部变量、参数、全局变量或值类型方法中 this 的地址
sizeOf<T>() / alignOf<T>()类型的大小与对齐（字节，ULong），编译期求值，不需要 unsafe
fun main() {
    @Unsafe {
        var counter = 41
        val p = addressOf(counter)
        p.store(p.load() + 1)
        println(counter)                           // 42
    }
    println(sizeOf<(Int, Long)>())                 // 16
}
  • addressOf 的实参必须是可寻址的变量，不能是临时值或计算结果。值类型方法中 addressOf(this) 指向方法的局部副本，而不是调用方的变量。
  • 没有空指针值：Ptr(0uL) 是编译错误（运行期为零是未定义行为），可空指针用 Option<Ptr<T>>。
  • 悬垂、未对齐、越界的访问以及与其他线程的数据竞争，都由 unsafe 代码的作者负责。

借用托管数据的指针

GC 可能移动托管对象。需要把数组或字符串的内容交给 C 时，使用有作用域的借用，借用期间对象被固定：

函数传给 block 的值
MutableArray<T>.withDataPointer { p, count -> … }可写的元素指针与元素个数
Array<T>.withDataPointer { p, count -> … }只读的元素指针与元素个数
String.withUtf8Bytes { p, length -> … }只读的 UTF-8 字节指针与字节数（不保证以零结尾）
String.withCString { p -> … }以零结尾的副本；字符串含 U+0000 时抛出 IllegalArgumentException
String.fromCString(p) / String.fromUtf8(p, length)从原生内存复制并严格解码为新字符串

这些函数都是 unsafe 的。指针只在 block 执行期间有效，保存到外部之后使用属于未定义行为。

FunPtr 与回调

FunPtr<F> 是 C 函数指针，F 是描述原生签名的普通函数类型，各参数与结果必须是 C-FFI-safe 的。期望类型为 FunPtr<F> 时，::name 直接解析为该函数的原生地址：

@Extern(name = "qsort")
fun cQsort(base: Ptr<Unit>, count: ULong, size: ULong, compare: FunPtr<(Ptr<Unit>, Ptr<Unit>) -> Int>)

@NoGC
fun compareInts(a: Ptr<Unit>, b: Ptr<Unit>): Int {
    @Unsafe {
        val x = a.cast<Int>().load()
        val y = b.cast<Int>().load()
        return if (x < y) -1 else if (x > y) 1 else 0
    }
}

fun main() {
    val values: MutableArray<Int> = [5, 3, 9, 1]
    @Unsafe {
        values.withDataPointer { p, count ->
            @Unsafe { cQsort(p.cast<Unit>(), count.toULong(), sizeOf<Int>(), ::compareInts) }
        }
    }
    for (v in values) print(f"${v} ")             // 1 3 5 9
    println("")
}
  • 目标必须是 @NoGC 的顶层具名函数，不能是泛型、挂起、extern、成员或扩展函数；签名必须与 F 完全相同。lambda、局部函数、绑定引用和已有的函数值都不能转换为 FunPtr。
  • 没有期望类型时，val f = ::name 得到的是普通的托管函数值，之后不能再转换为 FunPtr。
  • FunPtr 没有构造函数，也不能在 Scoop 中调用；它只用于传给原生代码。这种静态回调只能由原生方在同一线程上同步调用。
  • 需要原生代码稍后、或在其他线程调用托管闭包时，使用核心库的 foreignCallback 注册协议：它返回静态 trampoline 与不透明 context 的组合，由原生 API 的 user-data 参数携带，并显式管理所有权（retainForeignCallback、releaseForeignCallback）。

原生全局变量

  • @Global var x: T = … 与 @ThreadLocal var x: T = … 声明可以取地址的原生全局存储或线程局部存储。类型必须是 GC-free 的，初值必须是编译期常量，不能带访问器或委托。
  • @Extern 也可以用于顶层 val/var，访问库中的数据符号；可写的 extern 变量还需要 @Global 或 @ThreadLocal 说明是否线程局部，类型必须是 C-FFI-safe 的。
  • 普通的顶层属性不需要这些注解，可以保存托管引用，但不能取地址。
@Global
var callCount: Long = 0L

fun main() {
    @Unsafe {
        val p = addressOf(callCount)
        p.store(p.load() + 1L)
    }
    println(callCount)
}

@InteriorMutable

标注 @InteriorMutable 的 struct 表示其内容可能被改变（例如包含原子字段，或会被 C 代码修改），不再保证值类型的不可变性。这样的 struct 及其值只能在 unsafe 上下文中使用；复制仍然产生两份独立的存储。

Cone 中的 C/C++ 源码

manifest Cone 可以在 [native] 中配置随 Cone 编译的 C/C++ 源码：

[native]
include = ["native/include", { path = "native/linux", when = { os = "linux" } }]
c_flags = ["-O2", "-DUSE_FAST_PATH=1"]
cxx = true                       # 启用 C++
cxx_flags = ["-std=c++20"]

[[native.sources]]
path = "native/codec.c"

[[native.sources]]
path = "native/engine.cpp"

[[native.sources]]
path = "native/simd_x86.c"
when = { arch = "x86_64" }

[[native.libraries]]
name = "z"                        # 对应 @Extern(lib = "z")
kind = "dynamic"                  # default | dynamic | static | framework
  • native.sources 逐个列出文件，.c 按 C 编译，.cc/.cpp/.cxx/.C 按 C++ 编译；不会递归发现其他源码。when 与 源码选择的条件相同。
  • C++ 必须用 cxx = true 显式启用，C++ 链接需求会传递给最终程序。C++ 支持 Darwin/AArch64（libc++）、Linux/x86_64 GNU（libstdc++）以及三个 Windows 目标（MSVC 目标使用 MSVC STL，LLVM-MinGW 目标使用 libc++），不支持 musl。C++ 代码通过 extern "C" 包装函数与 Scoop 互操作，C++ 异常不能穿越 FFI 边界。
  • 编译选项按 argv 元素传递，不经过 shell。目标、sysroot、输出位置由工具链管理，不能通过选项覆盖。MSVC 目标的选项使用 Microsoft 驱动的写法（/I、/FI、/D、/U 等）；默认使用 /MD、C11/C++20、/EHsc 与 UTF-8 源码字符集，不能用选项切换 /MT、/MDd 或 LTCG。
  • 预处理器为当前目标定义 SCOOP_TARGET_OS_DARWIN/SCOOP_TARGET_OS_LINUX、SCOOP_TARGET_ARCH_AARCH64/SCOOP_TARGET_ARCH_X86_64 与 SCOOP_TARGET_ENV_NONE/_GNU/_MUSL；Windows 目标定义 SCOOP_TARGET_OS_WINDOWS，以及 SCOOP_TARGET_ENV_MSVC_UCRT、SCOOP_TARGET_ENV_LLVM_MINGW_UCRT 或 SCOOP_TARGET_ENV_LLVM_MINGW_MSVCRT 之一。公开的运行时头文件 scoop_rt.h 自动可用。
  • 单文件模式不读取 [native]。

系统库

[[native.libraries]] 声明要链接的逻辑库名，与 @Extern(lib = …) 合并处理，需求沿依赖闭包传递。库依次在显式的库目录、Scoop sysroot 与目标平台的默认目录中查找；交叉编译时不会回退到宿主的系统目录。framework 只用于 macOS。Windows 上逻辑名 L 按 L.obj、L.o、L.lib、libL.a、libL.dll.a 查找，既可以是静态库也可以是 DLL 的 import library；系统 DLL 写作 name = "user32" 这样的逻辑名。@Extern 也可以访问 DLL 导出的数据符号。

Scoop ABI

@Extern(abi = "scoop") 声明使用 Scoop 自身调用约定的原生函数：托管引用直接以引用值传递，被调方可以读取类型描述，并按运行时的 native-root 协议进入可能触发 GC 的运行时操作。它主要供运行时与核心库的实现者使用，调用点不要求 unsafe（除非声明显式标注 @Unsafe）；违反借用与保活规则属于运行时 ABI 错误。相关的 pin/unpin、getGcHandle/releaseGcHandle 与回调注册协议见 语言规范第 14 章和运行时规范。
