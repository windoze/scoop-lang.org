泛型

函数、class、struct、enum、interface 与类型别名都可以声明类型参数。Scoop 的泛型采用单态化：每组具体的类型实参生成一份专门的代码，没有类型擦除。所有类型参数都是不变的，没有 in/out 型变和 * 投影。

声明与使用

struct Pair<A, B>(val first: A, val second: B)

class Stack<T> {
    private val items = ArrayList<T>()
    fun push(value: T) {
        items.add(value)
    }
    fun pop(): T = items.removeAt(items.size - 1L)
    fun <R> peekMap(transform: (T) -> R): R = transform(items[items.size - 1L])
}

fun <T> firstOf(values: Array<T>): T = values[0]

fun main() {
    val stack = Stack<Int>()
    stack.push(1)
    stack.push(2)
    println(stack.peekMap { it * 10 })        // 20
    println(stack.pop())                      // 2
    println(firstOf(["a", "b"]))
    val p = Pair(1, "one")                    // 推断为 Pair<Int, String>
    println(p.second)
}
  • 每个完整的类型 application 都是独立的类型：Pair<Int, String> 与 Pair<Long, String> 互不相关，即使布局相同。
  • 在类型位置必须写出全部类型实参：Box 单独作为类型是编译错误，也没有 Box<*>。
  • 因为没有擦除，is/as 可以检查完整的类型实参（x is Box<Int>），泛型函数中可以使用 typeInfo<T>()、sizeOf<T>() 等依赖具体类型的操作，不需要 reified。
  • 没有预定义的 Self 类型：接口要表达“实现者自身的类型”时，用显式的类型参数，例如 Equals<T>、Compare<T>。

类型实参与推断

调用泛型函数或构造泛型类型时，类型实参通常由实参与期望类型共同推断，推断结果不依赖实参的书写顺序。也可以显式写出类型实参，并用 _ 让某些位置继续推断：

fun <A, B> convert(value: A, transform: (A) -> B): B = transform(value)

struct Pair<A, B>(val first: A, val second: B)

fun main() {
    val text = convert<Int, _>(3) { it.toString() + "!" }
    val pair = Pair<Long, _>(1L, "one")
    val empty: Array<String> = []                 // 由期望类型确定元素类型
    println(f"${text} ${pair.first} ${empty.size}")
}
  • 显式列表必须覆盖被调函数自己声明的全部类型参数，_ 只能出现在调用或构造的类型实参列表中。
  • 调用泛型类型上的方法时，只写方法自己的类型参数；宿主的类型实参来自接收者。
  • 推断必须为每个类型参数找到唯一的解，不会用 Any 或上界去“猜”。无法确定时，请补充类型实参或期望类型。

不变性

即使 Dog 是 Animal 的子类型，Array<Dog> 也不是 Array<Animal>，Option<Dog> 也不是 Option<Animal>。这一规则适用于所有类型参数，包括值类型：编译器不会为了赋值而重建或装箱整个容器。

interface Animal {}
class Dog : Animal

fun main() {
    val dogs: Array<Dog> = [Dog()]
    val animals: Array<Animal> = dogs     // 编译错误：Array 是不变的
}

需要“接受某个类型的任意子类型的容器”时，把消费操作写成带上界的泛型函数；需要转换容器时，显式构造或 map 出目标类型：

interface Animal {
    fun name(): String
}

class Dog : Animal {
    override fun name(): String = "dog"
}

fun <T : Animal> names(animals: Array<T>): Long {
    for (a in animals) println(a.name())
    return animals.size
}

fun main() {
    val dogs = [Dog(), Dog()]
    println(names(dogs))                                   // 直接接受 Array<Dog>
    val animals = Array<Animal>(dogs.size) { i -> dogs[i] }   // 显式构造新数组
    println(animals.size)
}

类继承与接口实现仍然产生普通的子类型关系：class IntList : ListBase<Int> 使 IntList 是 ListBase<Int> 的子类型，但不是 ListBase<Any>。函数类型本身的参数逆变、结果协变不受这条规则影响。

上界与 where 子句

T : Bound 要求类型实参是 Bound 的子类型，同时允许在函数体中使用 Bound 的成员。多个约束写在声明后的 where 子句中：

interface Named {
    fun name(): String
}

fun <T : Compare<T>> largest(a: T, b: T): T = if (a > b) a else b

fun <T> label(item: T): String where T : Named, T : ToString =
    item.name() + " " + item.toString()

struct Tag(val text: String) : Named, ToString {
    override fun name(): String = "tag"
    public override fun toString(): String = text
}

fun main() {
    println(largest(3, 7))
    println(largest("apple", "pear"))
    println(label(Tag("x")))
}
  • 同一参数至多有一个 class 上界，可以有多个不同的 interface 上界。
  • 上界必须是参数完整的 class 或 interface application，例如 T : Base<String>；不能是值类型、函数类型、Any 或另一个类型参数。
  • 上界可以引用被约束的参数本身：T : Equals<T> 表示“T 能与 T 比较”。
  • 上界是名义的：类型必须显式声明实现了该接口。只有同名方法而没有声明实现的类型不满足上界。
  • 对受约束的类型参数，只能使用上界提供的成员；没有上界的 T 甚至不能调用 toString()。

value 与 ref 约束

T : value 要求类型实参是值类型（struct、enum、tuple、基本类型），T : ref 要求是引用类型。它们主要用于 FFI 与底层容器，例如 Ptr<T : value>。kind 约束不能与 class/interface 上界同时用于同一参数。

fun <T : value> byteSize(value: T): ULong = sizeOf<T>()

fun <T : ref> sameObject(a: T, b: T): Boolean = a === b

fun main() {
    println(byteSize((1, 2L)))          // 16
    val s = "x"
    println(sameObject(s, s))
}

泛型方法的限制

  • 接口方法不能声明自己的类型参数（接口本身可以是泛型的）：interface I { fun <T> f(v: T) } 是编译错误。
  • class 中的泛型方法必须是 final 的，不能 open、abstract 或 override；它们总是直接调用，不经过虚分派。
  • 泛型方法有两组类型参数：宿主的类型实参由接收者决定，方法自己的类型实参由调用推断。两组参数不能重名。
  • 泛型函数的函数引用必须由期望类型确定全部类型实参，Scoop 没有“仍然是泛型”的函数值。

这些限制是单态化与固定虚表的直接结果。需要按类型分派的多态行为时，把类型参数提升到接口或类上：interface Visitor<R> { fun visit(node: Node): R }。

终止性

  • 多态递归不受支持：泛型函数递归调用自身时若改变了类型实参（例如 f<T> 调用 f<Array<T>>），单态化无法终止，这是编译错误。
  • 值类型的内联布局必须有限：struct Node<T>(val value: T, val next: Node<T>) 是编译错误。递归结构需要经过引用，例如改用 class 并把字段声明为 Node<T>?。

高级约束

以下约束只能用于有自己类型参数的函数（顶层、局部、扩展函数以及非接口的 final 泛型方法）。

负向约束

T : !I 要求类型实参确定不实现接口 I，常用来为“实现了 I”与“没有实现 I”的类型分别提供重载：

interface Debug {
    fun debug(): String
}

struct Point(val x: Int) : Debug {
    override fun debug(): String = f"Point(${x})"
}

fun <T : Debug> render(value: T): String = value.debug()
fun <T : !Debug> render(value: T): String = "<no debug view>"

fun main() {
    println(render(Point(1)))
    println(render(42))
}

负向条件只检查静态类型，只有确定成立时才能使用该候选；对未知的类型参数不会把“不知道”当作“没有实现”。

companion 约束

where T.Companion : I<T> 要求类型实参直接拥有一个 public companion，并且该 companion 实现了 I<T>。在函数体中可以用 T.Companion 访问它，T.method(…) 等价于 T.Companion.method(…)。这让“工厂”“解析器”“编解码器”这类按类型提供的能力可以静态选择：

interface Parser<T> {
    fun parse(text: String): T
}

struct Celsius(val degrees: Long) {
    public companion object : Parser<Celsius> {
        override fun parse(text: String): Celsius = Celsius(text.charLength)
    }
}

fun <T> parseAll(texts: Array<String>): ArrayList<T> where T.Companion : Parser<T> {
    val result = ArrayList<T>()
    for (t in texts) result.add(T.parse(t))
    return result
}

fun main() {
    val values = parseAll<Celsius>(["12", "345"])
    println(values[1].degrees)
}

只能使用类型自己直接声明的 companion，不会回退到基类的 companion。核心库与 JSON 等库用这种约束提供 Json.encodeToString(value) 这样无需显式传入编解码器的重载，见编解码。

成员要求

where requires(…) { … } 声明对类型实参公开成员的结构要求：

class Tagged(val text: String) {
    public fun label(): String = "tag " + text
}

class Version(val major: Int) {
    public fun label(): String = f"v${major}"
}

fun <T> describe(value: T): String where requires(v: T) { v.label(): String } =
    value.label()

fun main() {
    println(describe(Tagged("x")))
    println(describe(Version(2)))
}
  • 要求块中列出方法调用（必须写出结果类型）或构造调用 T(text: String)；T.method(…) 形式要求 companion 上的方法。可以在要求前标注 suspend、@NoGC 或 @Unsafe。
  • 只查找类型自身公开的成员（包括继承的成员），不考虑扩展函数或调用点的可见性。
  • 函数体先使用名义上界提供的成员，只有上界中没有适用目标时才使用要求。要求不提供运算符能力。

需要按名义接口组织能力时，优先使用普通上界；成员要求适用于无法为已有类型添加接口实现的场合，例如测试库的 assertEquals 同时支持实现了 Equals 与只具备结构相等的类型。
