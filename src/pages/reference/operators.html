运算符与相等

Scoop 的运算符大多是对 operator 函数的调用约定：a + b 就是 a.plus(b)。函数必须显式标注 operator，只有约定的名称不够。相等 == 同样通过成员 operator fun equals 决议，Any 没有任何隐式的相等、字符串化或哈希能力。

声明运算符

struct Vec(val x: Int, val y: Int) : ToString {
    operator fun plus(other: Vec): Vec = Vec(x + other.x, y + other.y)
    operator fun unaryMinus(): Vec = Vec(-x, -y)
    operator fun times(k: Int): Vec = Vec(x * k, y * k)
    operator fun compareTo(other: Vec): Long = lengthSquared().compareTo(other.lengthSquared())
    fun lengthSquared(): Long = (x * x + y * y).toLong()
    public override fun toString(): String = f"(${x}, ${y})"
}

fun main() {
    val a = Vec(1, 2)
    val b = Vec(3, 4)
    println(a + b)        // (4, 6)
    println(-a * 3)       // (-3, -6)
    println(a < b)        // true
}

除 equals 外，运算符函数必须是成员函数或扩展函数，可以是泛型、挂起或 infix 的。operator 标记属于覆写契约，覆写时必须保持一致。名称不在下表中、参数个数或结果类型不符合要求，都是声明处的编译错误。

展开后按普通的成员与扩展调用决议，只考虑带有对应 operator 标记的候选，并完整支持默认参数、vararg 与泛型。以下运算不能重载：&&、||、===、!==、赋值 =、?:、!!、?.、is、as。

class Grid(val width: Long) {
    private val cells = MutableArray<Int>(width * width) { 0 }
    operator fun get(row: Long, col: Long): Int = cells[row * width + col]
    operator fun set(row: Long, col: Long, value: Int) {
        cells[row * width + col] = value
    }
    operator fun contains(value: Int): Boolean {
        for (c in cells) if (c == value) return true
        return false
    }
}

class Adder(val base: Int) {
    operator fun invoke(x: Int): Int = base + x
}

fun main() {
    val grid = Grid(3L)
    grid[1, 2] = 7
    grid[1, 2] += 1
    println(grid[1, 2])      // 8
    println(8 in grid)       // true
    val add5 = Adder(5)
    println(add5(10))        // 15
}

e(args) 中，若 e 的类型是函数类型就直接调用；否则查找其 operator fun invoke。一次调用至多应用一次 invoke：若 invoke 返回的仍是可调用的值，需要再写一组括号。

复合赋值与自增自减

a op= b（op 为 + - * / %）同时考虑 opAssign 与普通 op：

  1. 只有 opAssign 适用时，调用它，不写回，因此接收者可以是 val；
  2. 只有 op 适用时，计算 a op b 并写回 a，此时 a 必须可写，结果必须能赋给 a 的类型；
  3. 两者都适用时是歧义错误，编译器不会擅自偏好其中一个。

++a/--a 读取旧值、调用 inc/dec、写回新值，结果是新值；a++/a-- 的结果是旧值。操作数必须是可写的位置；接收者和下标只求值一次。下标位置的复合赋值通过同一接收者的 get 与 set 完成。

class Bag {
    val items = ArrayList<Int>()
    operator fun plusAssign(value: Int) {
        items.add(value)
    }
}

struct Counter(val n: Int) {
    operator fun inc(): Counter = Counter(n + 1)
}

fun main() {
    val bag = Bag()            // val 也可以：plusAssign 不写回
    bag += 3
    bag += 4
    var c = Counter(0)
    c++
    val after = ++c                        // 前缀形式的结果是新值
    println(f"${bag.items.size} ${c.n} ${after.n}")   // 2 2 2
}

infix 函数

标注 infix 的成员或扩展函数可以写成 a name b，等价于 a.name(b)。infix 函数必须恰有一个必需的、非 vararg 的参数，调用时必须显式写出接收者（在当前对象上调用写作 this name b）。中缀调用左结合，优先级见运算符优先级。

struct Money(val cents: Long) {
    infix fun split(parts: Long): Money = Money(cents / parts)
}

fun main() {
    val share = Money(1000L) split 4L
    println(share.cents)               // 250
    println(0xFF and 0x0F)             // 整数位运算也是 infix 函数
}

位置解构

class 与接口可以通过 operator fun component1()、component2()……支持 val (a, b) = x 形式的位置解构。写出的 N 个位置会依次调用 component1 到 componentN，包括写成 _ 的位置；这种解构不能使用 ..。struct 与 tuple 的解构是内建的，不会调用 componentN。

class Entry(val key: String, val value: Int) {
    operator fun component1(): String = key
    operator fun component2(): Int = value
}

fun main() {
    val (k, v) = Entry("answer", 42)
    println(f"${k}=${v}")
}

迭代

for (x in source) 调用 source 上唯一的 operator fun iterator()，返回值必须实现 Iterator<T>，其 next() 返回 Some(值) 或在耗尽时返回 None。实现 Iterable<T> 是提供 iterator 的常规方式：

class Countdown(val from: Int) : Iterable<Int> {
    public override operator fun iterator(): Iterator<Int> = CountdownIterator(from)
}

class CountdownIterator(var current: Int) : Iterator<Int> {
    public override fun next(): Option<Int> {
        if (current < 0) return None
        val value = current
        current--
        return Some(value)
    }
}

fun main() {
    for (i in Countdown(3)) print(i)     // 3210
    println("")
}

相等

a == b 从 a 的静态类型（包括继承的成员与类型参数的上界）中查找带 operator 标记的成员 equals，按普通重载规则选出唯一目标并调用；a != b 对结果取反。两侧各求值一次，不交换操作数。

  • 找不到目标是编译错误。不存在 Any.equals，也不会回退到地址比较：静态类型为 Any 的两个值不能用 == 比较。
  • operator fun equals 必须是成员函数，恰有一个参数并返回 Boolean，不能是泛型或挂起函数；扩展函数不能声明 equals 运算符。
  • 值类型（struct、enum、tuple）在字段都可以比较时自动获得结构相等，见结构相等。
  • class 不会自动获得相等：需要按值比较时自己声明 operator fun equals；需要比较是否同一对象时使用 ===。
  • === 与 !== 比较引用 identity，只能用于引用类型，不能重载。同一对象的不同接口视图相等。
  • 编译器不假设用户的 equals 满足自反、对称或传递性，不会据此优化比较。

Equals 接口

泛型代码通过普通接口 Equals<T> 表达“可以比较”的能力。T : Equals<T> 使函数体中可以使用 ==：

public interface Equals<T> {
    public operator fun equals(other: T): Boolean
}
class Money(val cents: Long) : Equals<Money>, Hash, ToString {
    public override operator fun equals(other: Money): Boolean = cents == other.cents
    public override fun hash(): Long = cents.hash()
    public override fun toString(): String = f"${cents / 100L}.${cents % 100L}"
}

fun <T : Equals<T>> countOf(items: Array<T>, target: T): Int {
    var n = 0
    for (item in items) if (item == target) n++
    return n
}

fun main() {
    val prices = [Money(150L), Money(299L), Money(150L)]
    println(countOf(prices, Money(150L)))      // 2
    println(Money(150L) === Money(150L))       // false：不同对象
    println(Money(1234L))                      // 12.34
}
  • 类型必须显式声明实现 Equals<T>；只有同签名的 equals 方法，或值类型自动获得的结构相等，都不会使类型满足 T : Equals<T>。
  • 核心库中 Boolean、Char、整数、浮点、String、Unit 与 Ptr<T> 实现了 Equals；数组、函数值没有相等。
  • Equals<Base> 不会自动成为 Equals<Derived>。
  • 也可以自定义声明了 operator fun equals 的接口作为上界，运算符决议不要求特定的核心库接口。

ToString

public interface ToString {
    public fun toString(): String
}

print、println、f-string 插值和 StringBuilder.append 都要求 T : ToString，没有对任意类型的字符串化回退。class、object、struct、enum 都必须在声明中显式列出 ToString 并实现它（public override fun toString()）；字段实现了 ToString 不会让宿主自动获得它。tuple 与 Unit 不实现 ToString。泛型类型可以用条件接口实现在元素可打印时才实现 ToString。

需要调试输出任意结构时，可以使用核心库的 ValueInspector 与 DebugPrinter，见值观察与调试输出。

Hash

public interface Hash {
    public fun hash(): Long
}

Hash 没有任何默认或自动派生的实现。核心库为 Boolean、Char、八种整数与 String 提供基于内容的实现；浮点数不实现 Hash。作为 HashMap 等哈希容器的键时，类型需要同时实现 Equals<T> 与 Hash，并保证 equals 为真的两个值有相同的哈希值——这是库作者的责任，编译器不做检查。哈希算法的具体数值不保证跨版本稳定。

core 运算符接口

核心库还为每种运算符提供普通的泛型接口，供泛型代码声明所需的运算能力。它们与运算符的可用性无关：一个类型只要有合适的 operator 成员或扩展就能使用运算符，接口只在需要作为上界时才必须显式实现。

fun <K : Add<K, K>> sum3(a: K, b: K, c: K): K = a + b + c

fun main() {
    println(sum3(1, 2, 3))         // 6

}

泛型函数体中的运算符在定义处就绑定到上界接口的方法，具体化时调用实际类型的实现；调用方之后导入的扩展不能补救定义处不成立的运算。
